1. 当前 P0/G06 工程事实有效，`daily_loss_limit` 的 RB 交易日日切已经修复。

3. 方案 C（日内重置且阈值仍为 5）在已观察轨迹中零触发，不能宣称为有效保护。
4. 方案 B（关闭连续亏损门控）必须作为测量信号链本身的实验基线。

6. 方案 A（人工复位）适合作为实盘账户安全闩，不适合作为无人值守策略研究的唯一恢复政策。
7. OPEN-005 必须独立实施、独立重跑；不能与 P1 Setup 状态机一起改变。

因此，本轮不批准直接实现 D，也不批准把 C 设为正式规则。正式裁决是：

- **通过 B 作为必跑对照组。**

- **当前策略代码保持不变。**

## 四、两份审查共同遗漏的关键契约

### 1. 连续亏损的观察单位尚未统一

当前 `RiskManager.on_fill()` 每调用一次就按本次 `pnl_points` 增减连续亏损计数。回测在一笔逻辑持仓完全平仓时调用一次；CTA 与 live 路径则在每次平仓成交回报时调用，支持部分成交。

这意味着规则名虽然写的是“连续亏损笔数”，实际可能出现：

- 回测按完整 trade 计数；
- CTA/live 按 partial close fill 计数；
- 同一逻辑持仓的多个部分成交可能连续加一，也可能被后续正收益部分成交重置。

当前严格配置的 `max_abs_position=1` 可能掩盖这一差异，但一旦允许多手、分批退出或部分成交，三端 parity 就可能失效。OPEN-005 冻结前必须明确：

> 连亏观察单位应是“完整逻辑持仓平仓后的费用后聚合净收益”，还是“每个平仓成交”。

建议采用前者，并以稳定的 position/trade identity 聚合；这是建议，尚未裁决。

### 2. D 至少缺少一个在途状态

三状态 `ACTIVE -> PAUSED -> PROBE_AVAILABLE` 不足以表达 probe 已开仓但尚未平仓的情况。最小可审计状态机至少需要：

```text
ACTIVE
PAUSED_UNTIL_NEXT_SESSION
PROBE_AVAILABLE
PROBE_IN_FLIGHT
```

否则，probe 持仓跨交易日时可能错误地再次获得 probe 权限。

### 3. probe 的消耗点和结果点未定义

正式实验前必须逐项冻结：

- accepted signal、订单提交、首次开仓成交、全部开仓成交，哪一个事件消耗 probe；
- 订单被拒、撤单、零成交和部分成交如何处理；
- probe 无信号时是继续保留，还是在 session 结束时过期；
- 以费用后完整持仓净收益还是单次 fill 收益判定成功；
- 零收益属于成功、失败还是保持状态；
- 反手、强平、换月、样本末尾强制平仓如何解析 probe 结果；
- probe 盈利平仓后是立即恢复 ACTIVE，还是下一 session 才恢复；
- 账户级安全闩拒绝 probe 时，probe 权限是否仍保留；
- 重启后需要持久化哪些 state、probe id、关联 position id 和 session key。

## 五、数据预检查

连续口径中 173 个 `max_consecutive_losses` 拒绝信号分布在 132 个 RB 交易日：

| 每交易日拒绝信号数 | 交易日数 |
| ---: | ---: |
| 1 | 99 |
| 2 | 25 |
| 3 | 8 |

单日最多 3 个拒绝信号，33 个交易日存在多个拒绝信号。这说明“一 session 一 probe”不会在静态计数上完全等同于关闭门控；但 probe 一旦成交，会改变持仓、退出、信号消费及后续路径，所以绝不能用 `173 - 132` 推算交易数或收益。D 必须做真正的路径依赖反事实回测。

## 六、下一步执行顺序

1. 先冻结“亏损观察单位”和 B 的实验契约；B 只关闭 `max_consecutive_losses`，其他数据、规则、费用和风险门控保持一致。

4. 只实施 D，使用与 B 完全一致的数据和成本假设做独立反事实重跑。
5. 按风险调整收益、最大回撤、尾部损失、probe 成功率、恢复时间、交易覆盖率、年度/走势分层稳定性裁决；不得只比较总点数。
6. OPEN-005 稳定后再进入 P1 Setup 生命周期，最后再研究 G01/G02/G05 等策略经济性。
